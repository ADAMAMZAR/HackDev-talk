Incident report · Case 02Public GitHub, 2024–2025

Secrets leak fast

Leo's keys sat in his frontend code. He's not unusual.

GitGuardian, State of Secrets Sprawl 2025 · TechRadar

"Leo's API keys were sitting in his frontend code. He's not unusual."

"GitGuardian scans public GitHub every year. In 2024 they found 23.8 million leaked secrets: passwords, API keys, database logins."

[Space] "In 2025 it jumped to about 29 million, and commits written with AI help leaked secrets at roughly double the normal rate."

[Space] "The scariest number: 70% of the secrets leaked in 2022 were still working years later. People leak a key and never change it."

Cause of incidentCase 02

Two ways keys escape.

01

In frontend code

Anything sent to the browser is public, because anyone can open DevTools.

02

Committed to Git

Deleting the file later doesn't help. It's still in the history, and bots scan new public commits constantly.

…and the AI puts the key wherever the code works fastest. Usually the worst possible place.

"There are two ways keys escape. First, you put the key in frontend code. Anything sent to the browser is public, because anyone can open DevTools."

[Space] "Second, you commit it to Git. Deleting the file later doesn't help, because it's still in the history. Bots scan new public commits constantly."

[Space] "And the AI puts the key wherever it makes the code work fastest. That's usually the worst possible place."

Remedy · Case 02The .env fix

Move the key off the browser.

TRAP

NEXT_PUBLIC_ and VITE_ variables are shipped to the browser. A .env file alone isn't safe. The key also has to be used only on the server.

▶ Live demo StudyBuddy /fixed

[ON SCREEN] Show .env, .gitignore and app/api/chat/route.js in StudyBuddy. Then open /fixed, search sk- again, and find nothing.

Cause of incidentCase 03

The key is an address. RLS is the lock.

The public key

Supabase and Firebase let the browser talk straight to the database with a public key. It's supposed to be public. It's like the address of the building.

Row Level Security

The lock on each table. When AI tools create tables with raw SQL, RLS is often left off. No lock means anyone with the address walks in.

hiding a button in your UI is not a lock. the attacker never uses your UI.

"Supabase and Firebase let the browser talk straight to the database using a public key. That key is supposed to be public. It's like the address of the building."

[Space] "The lock on each table is called Row Level Security, or RLS. When AI tools create tables with raw SQL, RLS is often left off. No lock means anyone with the address walks in."

[Space] "And hiding a button in your UI is not a lock. The attacker never uses your UI. They talk to your database directly."

Remedy · Case 04AMCP servers, extensions, plug-ins

Anything you plug into your AI gets your access.

  1. Install it from the real publisher. Follow the link in the company's own docs, not a search result.
  2. Pin the version. The first 15 versions were fine and 1.0.16 wasn't. Read what changed before you update.
  3. One key per tool, smallest scope. If a tool turns bad, you revoke one key, not everything.

already installed a bad one? rotate every key it could see.

"Anything you plug into your AI gets your access. So:"

[Space] "Install it from the real publisher. Follow the link in the company's own docs, not a search result."

[Space] "Pin the version. The first 15 versions were fine and 1.0.16 wasn't. Read what changed before you update."

[Space] "Give each tool its own key with the smallest scope, so if one turns bad you revoke one key, not everything."

[Space] "And if you already installed a bad one, removing it isn't enough. Rotate every key it could see."

Transition: "Even code from the right publisher goes stale."

Cause + remedy · Case 04C4 safeguards

An instruction in a chat is not a permission.

The agent was holding the keys to the real database. If the agent can delete production, one day it might.

  1. Separate dev and prod databases. Replit itself added this after the incident.
  2. Never give an agent production credentials.
  3. Approval prompts for commands that delete, push or migrate.
  4. Backups exist before you need them.
▶ Live demo Agent console :5100
